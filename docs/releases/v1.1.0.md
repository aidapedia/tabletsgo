Tabletsgo v1.1.0 runs one image in two modes: **solo**, for one person with nothing else to run, and **enterprise**, for a team, where sign-in, workspaces, groups, roles and who may open each connection come from [Hayat](https://github.com/aidapedia/hayat). Tabletsgo no longer keeps accounts of its own in enterprise mode, so a v1.0 install with several accounts has to choose a mode when it upgrades. Read **Upgrading** before pulling.

## Highlights

### Solo mode
For one person, Tabletsgo needs nothing but Docker: `docker run -d -p 3000:3000 -v tabletsgo-data:/app/data ghcr.io/aidapedia/tabletsgo`. A new instance prints a six-word setup code to its log, so only someone who can read the log can claim it. Enter it with your name, email and a password, and you own the instance and its one workspace. With `ENCRYPTION_KEY` unset, a new solo install generates one into `/app/data/encryption.key`. A forgotten password is reset with `npm run solo:reset-password` inside the container.

### Enterprise mode with Hayat
For a team, start with the overlay: `docker compose -f docker-compose.yml -f docker-compose.enterprise.yml up -d`. People sign in at Hayat (OpenID Connect, authorization code + PKCE) with one account across every app that uses it. Workspaces are Hayat tenants, and people, rosters, groups, roles and grants are managed in Hayat's console. Tabletsgo reads them and links there. Opening a connection is the `tabletsgo.connection.open` permission, and a connection's **Access** tab shows who has it. `npm run hayat:bundle` writes the bundle that `hayat import` loads to register tabletsgo, and `hayat import` prints the `HAYAT_*` values to set.

### Which mode starts
`TABLETSGO_MODE` (`solo` or `enterprise`) when it is set. Otherwise the mode the instance recorded the first time it ran. On a new instance, enterprise when `HAYAT_ISSUER` is set, else solo. An instance that has run in enterprise mode never falls back to solo: if a `HAYAT_*` value goes missing, it refuses to start.

### Moving from solo to enterprise
A solo instance moves to enterprise with its connections, storage destinations, workspace and settings, and the owner keeps their id and everything they own. Write the bundle with `npm run hayat:bundle -- --out /app/data/hayat-import.json`, load it with `hayat import`, set `ENCRYPTION_KEY` and the `HAYAT_*` values, restart with the enterprise overlay, then sign up at Hayat with the owner's email. Going back from enterprise to solo in place isn't supported.

### Account themes
Each account has one theme, the same in every app you sign in to: presets, light/dark, every color (accent, content, sidebar, status), text size, density, corners, sidebar and content width, and font, with a live preview and a readability check. In enterprise mode it is edited in Hayat's console. In solo mode it is edited at **Setting → Appearance**.

### Fixes and polish
- Solo passwords are hashed with scrypt. Signing in gives a 15-minute access token and a 30-day refresh cookie, and a password change or **Setting → Account → Sign out everywhere** ends every session.
- Enterprise access tokens are verified offline against Hayat's keys, and every permission is asked of Hayat.
- Instance SMTP now only sends tabletsgo's own notices (backup failures, locked connections). Invites and password resets are Hayat's.
- `npm run dev:hayat` runs Hayat from source beside tabletsgo and seeds a Demo workspace with sample connections.

## Upgrading

Pull the new image and restart. The metadata database migrates on boot (migration `20261110000000_hayat_owns_identity`, SQLite and PostgreSQL), and a `pre-migrate` snapshot is taken first.

**A v1.0 install with its own accounts:**
- **To enterprise:** the first start writes everything the account tables held to `data/hayat-import-<time>.json` and then drops those tables. Load it with `hayat import --file data/hayat-import-<time>.json --app-url https://db.acme.com --out hayat-result.json`. If Hayat already knew some of those email addresses, also run `npm run hayat:remap -- hayat-result.json`. People keep their ids and passwords, workspaces keep their ids, and groups, rosters and connection access lists come along as Hayat grants. Google and GitHub sign-in links don't carry over, because sign-in methods are now Hayat's.
- **To solo:** with one account, start with no `HAYAT_*` set. That account becomes the owner, and every workspace's data moves into the one solo workspace. With several accounts the start stops and says so: deploy Hayat so everyone keeps access, or set `SOLO_OWNER=<email>` to keep that person and all the data (the others lose access).

New environment variables: `TABLETSGO_MODE`, `SOLO_OWNER`, and for enterprise `HAYAT_ISSUER`, `HAYAT_API_URL`, `HAYAT_CLIENT_ID`, `HAYAT_CLIENT_SECRET`, `HAYAT_WEB_CLIENT_ID` (required), plus `HAYAT_CONSOLE_URL` and `HAYAT_AUTH_URL` (optional). `ENCRYPTION_KEY` is now required only in enterprise mode.

Removed environment variables: `SESSION_TTL_MS` (a login is now a token, Hayat's or solo's), and `LOGIN_MAX_ATTEMPTS`, `LOGIN_ATTEMPT_WINDOW_MS`, `LOGIN_LOCKOUT_MS`, `LOGIN_ADMIN_COOLDOWN_MS` (sign-in is no longer tabletsgo's). Google/GitHub sign-in and the Registration module are gone; in enterprise mode, sign-up and sign-in methods are set in Hayat.
